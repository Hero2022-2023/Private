# 瞬影白名单 Surge 模块 v1.1.0（重制版）

瞬影播放链路的直连白名单，模块里只有三条规则，没有任何附加段落：

```
[Rule]
DOMAIN-SUFFIX,yd.emby.syemby.com,DIRECT
DOMAIN-SUFFIX,cmecloud.cn,DIRECT
DOMAIN-SUFFIX,139.com,DIRECT
```

为什么是这三个：瞬影 PRO 的服务器是 `yd.emby.syemby.com`，但点播后媒体流走 302 跳到 139 云盘——接口域名 `139.com`、文件数据域名 `cmecloud.cn`（移动云盘对象存储，实际形态如 `*.eos.*.cmecloud.cn`）。只放行服务器域名、媒体流仍走代理节点，播放照样失败，这正是 v1.0.1 实测失败的原因，本版把整条链路一起放行。

为什么直连：瞬影 PRO 只允许中国大陆 IP 访问、官方明令禁止代理工具，多地异地 IP 登录会封号，这三个域名必须用真实 IP 直接出去。

生效方式：按 Surge 官方手册，模块的优先级高于主配置，`[Rule]` 里的新规则会插入主配置规则列表的最前面，所以这三条先于主配置任何规则命中，最终策略组选什么都不影响。

## 版本

- v1.1.0（2026-11-14）：按用户实测反馈重制。去掉 v1.0.x 的 [General] / [MITM] 附加段落，只保留上面三条规则；模块名定为「瞬影白名单」。
- v1.0.1（2026-11-14）：瞬影专用单域名版，用户真机实测播放失败（媒体流域名未放行），已被 v1.1.0 取代。
- v1.0.0（2026-11-14）：初版。

## 安装

Surge → 修改 → 模块 → 安装新模块，粘贴永久地址（托管在主人 GitHub 仓库，`surge-whitelist/` 目录）：

```
https://raw.githubusercontent.com/Hero2022-2023/Private/main/surge-whitelist/Whitelist-Direct.sgmodule
```

已装旧版的，在 Surge 模块页对它点更新即可（地址不变，版本号会变成 1.1.0，模块名变成「瞬影白名单」）。装好后把播放器彻底关掉重开再播。

如果更新后仍然播不了，在 Surge「最近请求」里播一次瞬影，截一张图发我：重点看这三个域名命中的策略是不是 DIRECT、以及 302 之后实际出数据的域名是不是还有第四个域名，有就补进模块再推一版。

## 测试结果（2026-11-14，本地逐项模拟）

v1.1.0 通过 27/27：模块名/版本、只有 [Rule] 一段（无 General/MITM/Script）、三条规则与用户给的原文逐条一致（含顺序）、DOMAIN-SUFFIX 语义模拟命中 8 项（三个域名本身及其子域名形态）、不命中 9 项（含 syemby.com 其他子域、仿冒后缀形态）。

未在真机验证的部分以用户实测为准：本版是针对 v1.0.1 真机失败的修正，是否恢复正常播放需用户在 iPhone 上确认。
